## Where the ~186 KB came from

Nothing in the scene budget was traded. The bytes came out of the ARM9 static
image and out of a reservation the DS renderer does not use.

| lever | bytes | note |
|---|---|---|
| scene file store `.bss` -> scene arena | 185,696 | title / opening-action / Peach's-Castle file destinations; a VSBattle touches none of them |
| `NDS_TASKMAN_ARENA_SIZE` 0x17a000 -> 0x1a7000 | +184,320 target | spends the returned static image, keeps the post-arena libnds reserve unchanged |
| VSBattle DL buffers 2048+512 -> 512+128 `Gfx`, per context | +30,720 | measured use is still 16 B in buffer 0 and 0 in buffer 1 |

Predicted low-water before the run was 49,956 B; measured 49,956 B. The model
is exact because every term is a constant: r11's accepted 57,316, less the
restored 189,632 (pack) and 32,768 (cache trim), plus 184,320 of arena and
30,720 of DL buffer.

The arena still loses 36,864 B to the roster's larger ARM9 binary — AllocFail 9
against a 1,732,608 B target — exactly as it did at the old target. That term
is unchanged, not fixed.

## What it cost

* **Ticks: nothing measurable.** `ALL` P50/P95 **1,964,928 / 3,085,696** and
  `WORK-H` **1,500,032 / 2,625,152**, against r11's pack-off
  1,964,992 / 3,085,760 and 1,530,752 / 2,708,480. VBlank intervals
  `2:64 3:65 4:17 5+:1827`, max 21, slips 0 — the same distribution.
* **The pack bought nothing on this content set.** Restoring 189,632 B of
  Fox-only prebuilt clips moved P50 by −64 ticks, i.e. noise. It still costs
  what it costs on the two-fighter shipping arm, where its −34,304 was
  measured; on four distinct kinds it serves one fighter in four.
* `gNdsR2AnimCacheRejects` **132** (misses 143), against r11's 212/216 and the
  mirror arm's 18/31. Restoring the trim recovered a third of the rejects.
  Every reject degrades to the on-demand load.
* No presentation, gameplay, capacity or fidelity change: the DL buffers hold a
  command stream nothing on this port writes, and the scene file store is
  allocated by the scenes that use it.

## The measurement this run banks for next time

`gNdsTaskmanGraphicsHeapHighWater` = **96 B** of a **53,248 B** per-context
reservation, `gNdsTaskmanGraphicsHeapOverflowCount` = 0, over the whole match.
Two contexts are allocated, so **106,496 B of the scene arena is holding 96 B
of live data** on this arm.

That is the largest single reclaim left in the battle arena and it was left
untaken deliberately: this sample covers one VS match. The graphics heap has
live source writers on paths this run does not exercise — the afterimage vertex
parking in `ftdisplaymain.c:457-581`, the Results/Sudden Death draw loop, the
pause zoom — so the size must be re-read on those before it is cut. The
counters are in `src/port/diagnostics.c` and the harness reads and asserts them.

proves any of those bytes are dead on DS; sizing them is the next row's work.
