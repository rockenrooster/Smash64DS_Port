# 02 — Build, link, and assets

Start from the repository's working build. Use matching devkitPro rules, compiler, libraries, ARM7 image and linker scripts. Do not replace the ARM7 service image merely to add a helper. Check architecture and instruction mode per CPU; an ARM9-only instruction cannot run on ARM7. Keep debug/release defines and generated asset options visible in reproducible build commands.

## Linker and C/C++ checks

Inspect the final map/ELF for code, rodata, data, BSS, TCM, alignment, stacks, and memory overlap. `const` linked into an ARM9 image still consumes its loaded memory; it is not automatically streamed from a cartridge. A smaller heap report can conceal larger static allocation. Include boot/runtime and transition peaks in admission.

Respect weak-symbol types and C linkage when overriding runtime hooks from C++. Static constructors, exceptions, RTTI, virtual dispatch, or allocation are choices to measure, not reasons to ban C++. Do not use blanket packing or ABI-dependent structs as file formats. [17](17-libnds2-calico-facts.md) covers Calico stack/linker details.

## Asset build contract

Host tools should emit deterministic, versioned native data with provenance, validated counts/offsets, explicit endianness and dimensions. Fail on unsupported semantics. Declare every source/palette/material input, converter and option dependency. Regenerate all affected consumers together, including offline caches. Measure layout/count pins from generated artifacts or ELF, then check independent semantic invariants and resource ceilings; never copy a failing assertion's requested value.

Choose native format deliberately: tiled versus linear; pixel dimensions versus tile counts or libnds texture-size enums; bits per pixel; palette ordering; alpha policy; alignment; and destination bank. Converter defaults that force opaque texels are not safe defaults for cutouts. Check generated bytes rather than trusting a preview PNG. See [05](05-vram-memory-and-assets.md).

Keep ROMs, extracted game assets, credentials and unrelated build products out of the skill package. Retain upstream license/attribution when adapting code.

Project build ownership, artifact identity and verifier commands live in `AGENTS.md` and `docs/VERIFYING.md`, not here. Host tests and freestanding ARM objects do not establish SDK linkage, boot, rendering or timing.
