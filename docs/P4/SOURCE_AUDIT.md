# Source re-review — what changed after the submodules became available

**Reviewed project:** `70e45e28d8e7b09545b1f772cf89f894452e9c5f`. See the exact [lock](source-lock.json).

This document records changes to the earlier provisional package. It does not assert that every assembly function or model was audited. The direct and nested Remix gitlinks agree; the old EXTRA sample at `6ea74fdb...` is not the project pin and is not used as evidence for this revision.

## Findings and consequences

| Area | Earlier assumption or risk | Pinned evidence | Required change |
|---|---|---|---|
| Source availability | Sources were missing from the public project; upstream examples were only provisional. | The project now pins two source submodules, and EXTRA pins the same Remix base as the direct submodule. | Use recursive gitlinks as source authority. Remove the earlier missing-local-checkout caveat and the unrelated EXTRA sample revision. |
| Importer contract | Same file/container format implies the existing production scripts can consume it. | Current generate_fighter_production_manifest.py reads BattleShip C/O2R metadata; Character.asm resolves parent/action data from ROM. | Implement two source front ends and one typed native-production contract, including semantic object/consumer metadata. |
| Event programs | moveset/*.bin are drop-in complete streams. | Falco appends pointers/loops and falls through; Wario builds idle in assembly; Marth uses concurrent and random-voice commands. | Export linked programs, validate control flow and pointer domains, then lower to the existing competitive DS representation. |
| Inheritance | One parent name explains behavior, models and dependencies. | Only vanilla IDs are legal setup parents; Roy uses Captain setup and many Marth assets. Shared routines can originate elsewhere. | Separate setup/action inheritance, resource donors, global callbacks and copy abilities. |
| Marth/Roy moves | A familiar later-game sword kit can fill details. | Marth declares three Dancing Blade stages; Roy has Flare Blade charge branches. | Derive actual state graphs and branch tests. Do not invent a fourth stage or reuse Counter for Roy by assumption. |
| Clock handling | One frame counter and a blanket 30-FPS rescale are sufficient. | Ganondorf uses an animation-speed-without-event-speed command; Dedede has a one-frame input buffer. | Separate event, animation and render clocks; validate any approved compensated simulation schedule. |
| Numeric accuracy | Assembly comments can supply port constants. | Lanky's Kirby origin uses float bits 0x43960000 = 300.0 while its comment says 200. | Decode the executed operands; add source numeric fixtures and inspect consumers before translating units. |
| MRGAW identity | Game & Watch is a generic 2D asset/standard later-game moveset. | MRGAW, PLUS and THREED are distinct; selected MRGAW wires Chef/Fire/Judge and flips top/weapon/grab X scales by facing. | Lock MRGAW; test nine Judge branches and signed native transforms. Do not add a down-special bucket from memory. |
| Kirby completeness | Every newcomer needs an invented unique copied neutral special, or Kirby can be postponed. | Snake separates grenade assets for Kirby; MRGAW sets a numeric hat mapping rather than declaring a new Chef copy in the inspected entry. | Resolve actual copy policy. Preload ability fragments; retain independent mutable state and lifecycle. Shared/no-copy source outcomes are valid. |
| Article budgets | A fixed guessed number of projectiles per character is enough. | Banjo has different forward/backward lifetime constants; Snake config names resource families without simultaneous caps. | Read creators, lifetimes and ownership/cap rules; size worst legal overlap, including copies and stock persistence. |
| Metal Mario | No loose moveset bins means a trivial parameter-only addition. | Pinned donor builds timed victory scripts; DS MMario exists as a nonselectable campaign resource variant. | Diff selectable donor mechanics against P2 reuse and qualify menu/audio/mode/record behavior separately. |
| Planning scope | New character files prove no blockers and predictable ASM-lines-per-hour effort. | Source presence is established; full dependency resolution, conversion, loaded sizes and runtime tests are not. | Keep Falco first and early Bowser/EXTRA/Snake risk probes; estimate from completed slices and explicit remaining dependencies. |

## Implementation gates are still open

No source ROM was reconstructed, no donor was assembled, no model/animation was converted, no DS ROM was built and no emulator/performance run was executed for this package. Source folder/file sizes are not converted DS resident sizes. Unknown fields in the lock remain null. The documentation's planned gate names are not claims that corresponding commands already exist.

The new source evidence strengthens the plan, but does not justify "all 18 fit" or "no blockers." It turns several vague risks into specific implementation tasks and test fixtures. That is the basis for starting Falco rather than writing speculative ports in parallel.
