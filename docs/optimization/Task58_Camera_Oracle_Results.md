# Task 58 — Dream Land Gameplay-Camera Error Oracle: Results

Host-only. Builds a deterministic screen-space visual-fidelity metric so later
mesh simplification (Task 59) is judged by what the player sees, not arbitrary
3D distance. No runtime/renderer changes.

## Deliverables

- `scripts/dreamland_camera_oracle.py` — fixture generator, projection,
  silhouette/protected-edge metric, `--build-reference` / `--compare` /
  `--self` / `--check` commands.
- `scripts/generated/dreamland_camera_fixtures.json` — 8 deterministic gameplay
  camera fixtures (regenerated by `--check`).
- `scripts/generated/dreamland_source_projection_ref.json` — the source Task-57
  mesh projected through every fixture (the pinned reference Task 59 compares
  against).

## Architecture

The renderer is camera-agnostic: it consumes pre-composed `projection ×
camera_modelview × binding_world` matrices
(`NDSRendererNativeStageFrame`, include/nds/nds_renderer.h:804). The Dream Land
default camera converges FOV to **38.0** (`gmCameraAdjustFOV(38.0F)`,
gmcamera.c:636) and tracks the live fighter centroid; the 2-player zoom range
multiplier is **1.32** (`dGMCameraPlayerZoomRanges[2]`, gmcamera.c:43).
Internal viewport ~320×240 (vscale 600/440, taskman_seam.c:5749).

**Key de-risk:** the oracle compares *source mesh vs candidate mesh* through
the **same** projection, so it does not need to bit-replicate the adapter's
fixed-point `guPerspective`+`guLookAt` build. It needs (1) fixtures grounded in
the real camera envelope and (2) a consistent perspective projection matching
the DS effective FOV/aspect. Same-projection-on-both-sides is what makes the
silhouette-displacement metric meaningful. The projection is float math,
deliberately — screen-space displacement in pixels is the measured quantity;
the runtime's bit-exact world transform is already proven by Task 57.

## Metric

Per fixture, comparing a candidate's projection to the source reference:

- `max_silhouette_displacement_px` — directed max (candidate→reference nearest)
  over the boundary-edge (silhouette) point set.
- `p95_silhouette_displacement_px`.
- `protected_edge_max/p95_displacement_px` — same, restricted to the
  auto-detected protected vertices.
- `projected_bbox_delta_px` — |Δmin/max x/y| of the projected bboxes.

**Protected edges** are auto-detected by topology: the 4 largest connected
components whose mean triangle normal tilts ≤15° from +Y (near-horizontal
top-facing surfaces = the main floor + 3 floating platforms). This yielded
**27 protected vertices** from the source mesh — no manual tagging.

Thresholds (configurable, plan starting values):
```text
protected_edge <= 0.5 px   (platform/fighting-surface edges, preferred)
silhouette     <= 1.5 px   (major silhouette)
decorative     <= 2.0 px   (low-priority surfaces)
```

## Verification (all gates pass)

`python scripts/dreamland_camera_oracle.py --check`:
1. **Determinism** — rebuilt fixtures + reference sha256-match the stored files.
2. **Validity** — finite eye/at/fov; invertible view-projection; non-empty
   silhouette per fixture (the source mesh is visible in all 8).
3. **Protected-edge determinism** — re-running yields the same 27 vertices.
4. **Identity probe** — `--self` reports **0.0000000000 px** worst displacement
   (source vs its own reference), proving the metric is self-consistent.

**Mutation tests** (confirm the gate is real, not a rubber stamp):

```text
perturbation                          worst_sil  worst_prot  fixtures FAIL
+50  world-Y on a high vertex         2.57 px    0.00 px     7/8  (silhouette)
+800 world-Y on a high vertex        41.52 px    0.00 px     8/8  (silhouette)
+200 world-X on a protected vertex    7.65 px    7.65 px     8/8  (both)
```

The metric scales linearly and both channels (silhouette + protected) respond.
A +50-unit perturbation correctly FAILs the 1.5 px silhouette gate; a
+200-unit perturbation of a protected vertex FAILs the 0.5 px protected gate.

## Notes for Task 59

- Task 59's simplifier runs `--compare` on every candidate against this
  reference; only candidates passing all 8 fixtures at the thresholds above are
  visually acceptable. The cheapest passing candidate wins (per the plan's
  "select the cheapest candidate that still looks acceptable").
- Protected edges are the hard constraint: a simplification that moves a
  platform edge by >0.5 px is rejected even if the overall silhouette is fine.
- The 27 protected vertices are a small fraction of the 255 dense vertices, so
  most of the mesh is available for aggressive simplification.
- Fixtures are pure functions of the stage bounds + camera constants, so they
  stay valid as long as Task 57's mesh is unchanged; a stage change regenerates
  them deterministically.
