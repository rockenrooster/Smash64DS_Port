# P2-2 semantic pack estimator — repository binding

`docs/reviews/Review_Deriving_Fighter_Live_After_Setup_Set.md` decided the
architecture and specified the estimator. This file binds that specification to
the files, parsers and constants that actually exist here, so the tool can be
built without re-deriving any of it. Read the review first; this does not
restate its reasoning.

**Deliverable: a read-only estimator. No runtime code, no loader, no poison
harness.** Its whole job is a go/no-go size verdict before the runtime work is
allowed to start.

## The verdict it must produce

```
F_new = 208,372 - W - D_other - D_binder          (bytes of free floor)
W <= 175,604 - D_other - D_binder                 (for a 32,768 B floor)
```

| Result | Condition | Meaning |
| --- | --- | --- |
| STOP | any unclassified atom or consumer | no size verdict is valid |
| RED | worst pack > `175,604 - D_other - D_binder` | the pack alone cannot hold the floor |
| YELLOW | worst pack ~150-175 KiB | fit depends on explicit secondary recovery |
| GREEN | worst pack <= ~150-160 KiB | build the runtime proof |

The 150-160 KiB band is provisional and must be replaced by a threshold
measured from a four-slot, pack-disabled skeleton build that isolates `D_other`
and `D_binder`.

## Input 1 — the file-level closure already exists

`scripts/fighters/fighter_production_manifest.json` (2.6 MB, generated by
`scripts/fighters/generate_fighter_production_manifest.py`) already gives, per
fighter: `core` (9 slots, each with `symbol` and an `asset` carrying `id`,
`path`, `bytes`, `data_bytes`, `alloc_bytes`, `sha256`), `core_extern_closure`
(the full file closure), `motion_files`, `event32_motion_files`,
`item_motion_file_count`, `nitrofs_files` and `special_status_contract`.

Do not re-derive any of that. It is the estimator's file layer, and
`alloc_bytes` is the figure `syTaskmanMalloc` is actually asked for — the same
numbers `include/nds/generated/nds_fighter_production.generated.h:10-21`
publishes as the census rows.

What the manifest does **not** have, and the estimator must add, is
**object-level** granularity inside those files.

## Input 2 — the object index comes from the relocData sources

`decomp/BattleShip-main/decomp/src/relocData/` holds 2,040 generated `.c` files
plus a `.reloc` table per file. They are typed C, which is what makes an object
graph possible at all. Measured shape, so the parser is written against fact:

- `229_KirbyMain.c` carries 19 objects with machine-readable headers of the form
  `/* @ 0x039C, 40 bytes: FTAttributes.sub_0x39C target (was dKirbyMain_pre+0x39C) */`.
  **These exist only in the `*Main` files.** Use them where present: they give
  offset, size and the consuming struct field for free.
- `328_KirbyModel.c` has **zero FT-style headers** but is not offset-blind, and
  a 2026-09-04 feasibility pass corrected an earlier reading of this file that
  said it was. It carries its own offset comments — `/* MObjSub @ 0xB0 */`
  (`:514`), `/* Vtx: Vtx_0x04B0_Vtx @ 0x4B0 (144 vertices) */` (`:780`),
  `DisplayList: Joint_0x0DB0 @ 0xDB0 (640 bytes, 80 cmds)` (`:785`),
  `DObjDesc: JointTree @ 0x1448` (`:820`) — and the symbol names themselves
  embed offsets (`dKirbyModel_Vtx_0x04B0_Vtx`,
  `dKirbyModel_gap_0x31CC_sub_0x8EC`). So offsets are **anchored**, not
  reconstructed: walk declarations in file order accumulating
  `N * sizeof(TYPE)`, and cross-check every step against the next offset
  comment and the offset embedded in the next name. It has 1,235 top-level
  declarations. Type histogram, which is also the disposition key:

  | Type | Count | Nature |
  | --- | ---: | --- |
  | `extern` | 363 | edges, not objects — including out-of-file donors |
  | `u8` | 170 | texel and palette banks |
  | `Vtx` | 163 | raw N64 vertex arrays |
  | `MObjSub` | 76 | material descriptions |
  | `u32` | 69 | mixed scalar/table |
  | `Gfx` | 61 | raw display lists |
  | `u16` | 41 | mixed |
  | `DObjDesc` | 8 | joint tree nodes |
  | `Sprite` | 2 | presentation |
  | `DObjDLLink` | 2 | display-list links |
  | `Bitmap` | 2 | presentation |

### The `.reloc` grammar, and why it is not sufficient alone

Per line: `<type> <ptr_label> <target_label>`, `#` comments. `type` is `extern`
or `intern`, `ptr_label` is `Symbol[+0xHEX]` naming the patch site as a byte
offset into the source object, and the target is `Symbol[+0xHEX]` or a bare hex
file offset. **Cross-file is distinguishable**: `extern` lines carry a
`# -> file N (Name)` suffix, `intern` is a same-file fixup. Worked rows:

```
229_KirbyMain.reloc:4    extern dKirbyMain_file_handles 0x154   # -> file 228 (KirbyMainMotion)
229_KirbyMain.reloc:108  extern dKirbyMain_modelparts_desc_0x39C 0xF8  # -> file 326 (LinkBoomerangModel)
229_KirbyMain.reloc:112  intern dKirbyMain_modelparts_container+0x8 dKirbyMain_modelparts_desc_0x0CC
328_KirbyModel.reloc:11  intern dKirbyModel_Joint_0x0020_post+0x4C 0x1CF60
```

It is **not** an object index on its own: it lists only patched slots, gives no
sizes, duplicates records (`328_KirbyModel.reloc:33-42` repeats the same five
DL→Vtx edges), omits NULL, pure-scalar and unreferenced objects entirely, mixes
named with anonymous bare-hex targets, and its intra-display-list edges point
into `.inc.c` bodies that are invisible in the `.c` text.

### The semantic edges it cannot express — the hand-rule list

Enumerated against Kirby, so the generator has a concrete checklist rather than
review §3.3's abstract category:

| Edge | Why reloc is silent | Example |
| --- | --- | --- |
| DObj parent-index hierarchy | plain int field, no pointer | `328_KirbyModel.c:830-832` |
| material-script texture selection | an integer id, not a pointer | `:901` `aobjEvent32SetVal(AOBJ_MATFLAG_TEXID, 50)` |
| texture → palette LUT binding | **exists only in a comment** | `:7678` `/* @tex fmt=CI4 dim=16x32 lut=... */` over `:7679` |
| joint-ID integers | index the joint tree, never relocated | `229_KirbyMain.c:549` `{6,16,22,27,11}` effect joints |
| `DObjDLLink` discriminator | the `1`/`4` tag has no reloc row | `328_KirbyModel.c:8072` |
| copy-hat atom sharing | reloc lists both pointers, not the dedup rule | `229_KirbyMain.c:252-261` |

**Parser hazards** that defeat a naive line scan, all present in this corpus:
`PAD()` lines that look like symbols but carry no type; declarations whose
bodies live in included `.inc.c` files; cast- and NULL-heavy initialiser rows
that hide edges from a text scan; `aobjEvent32...` macro word streams whose
commas are not object boundaries; and self-referential sentinels where an array
contains a cast pointer to itself (`328_KirbyModel.c:8135`).

**Verdict: the typed object index is mechanical.** Parse the `.c` declarations
for nodes and sizes, join `.reloc` for pointer edges, and layer the table above
as explicit rules. Caveat on the evidence: the Model file is 8,246 lines and the
rare-declaration sweep was done by grep, not a full line audit, so the parser
must fail closed on any declaration form it does not recognise.

## Input 3 — what the native owner already replaces

`include/nds/generated/nds_native_fighter_image.generated.h` holds the
per-fighter native image census. Those bytes are **resident, not free** (review
§2.4) and must be added to `W`, not subtracted. `scripts/fighters/generate_nds_native_owners.py`
holds the joint-tree offsets and descriptor counts per fighter, and
`scripts/fighters/admit_fighter.py` the admission rules.

## The disposition table this corpus needs

Every object gets exactly one disposition, and an object with none is a STOP.
Be aggressive only where the bytes are (review §1.1):

| Source objects | Disposition |
| --- | --- |
| `Vtx`, `Gfx` | replaced by the native owner; retain a native root ID |
| `u8` texel/palette banks, unselected costume | dropped |
| `u8` texel/palette banks, selected costume | uploaded to VRAM; retain handle + format |
| `MObjSub` | translated to a compact DS material record |
| `DObjDesc` joint tree | retained whole, both details |
| `FTAttributes` (0x348 B) | retained whole — four copies are 3,360 B; do not prove fields dead |
| `FTModelPart` rows | retained whole domain, including copy-hat rows |
| setup-only DObj/MObj scaffolding | consumed into per-instance state, then dropped |
| `Sprite`/`Bitmap` for CSS/Results | moved to that scene's pack, not battle-resident |
| file padding, relocation pointer arrays | dropped |

## Cross-fighter atoms

Kirby's copy-hat rows are the worked case and are already verified:
`229_KirbyMain.c:251-261` points `modelparts_desc_0x39C` at
`dLinkBoomerangModel_Joint_0x00F8_DisplayList` and `modelparts_desc_0x3C4` at
`dFoxUnknown_DL`. Give every object a canonical atom ID; a match pack is the
**union** of atom IDs, so a Link atom named by both Kirby's capability manifest
and Link's base manifest is counted once. Roster-conditional copy assets are
capabilities; unconditional cross-owner references stay base dependencies.
Kirby's absent donor entries must become explicit invalid values, never dangling
pointers.

## The enumeration

495 exactly-four-kind sets, and **793 proof cases** for the
one-through-four-kind sets (12 + 66 + 220 + 495). Enumerate all 793 for sizing.
There must be no 495 payload packs — only atoms and factored manifests.

Report: worst set, worst costume combination, worst feature profile, and an
exact byte ledger.
